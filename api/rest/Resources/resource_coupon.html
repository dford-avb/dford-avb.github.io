Allows you to retrieve salesrules.

URL Structure: https://magentotesting.avbportal.com/api/rest/salesrule

Version: 1

HTTP Method: GET /salesrule

Description: Allows you to retrieve the list of existing salesrules.
Notes:: Only Admin user can retrieve the list of salesrules.

Authentication: Admin
Default Format: JSON
Parameters:

Coupon Types: 

type
field in the response body 1=No Coupon (default) 2=Specific Coupon 3=Use Auto Generation

GET api/rest/salesrule and api/rest/salesrule/store/:store Returns a collection of Shopping Cart Price Rules, potentially filtering by store Supports standard Magento filtering and paging, see example below Shopping Cart Price Rules exist per website_id rather than per store_id, store_id is not returned Only Status: Enabled rules are returned (is_active=1) GET api/rest/salesrule/:id and api/rest/salesrule/:id/store/:store Returns all data for a single Shopping Cart Price Rule

HTTP Method: POST /salesrule

Description: Allows you to create a new salesrule.
Authentication: Admin
Default Format: JSON
Parameters:

POST api/rest/salesrule and api/rest/salesrule/store/:store Create a new Shopping Cart Price Rule Required fields: customer_group_ids, is_active, name, simple_action, website_ids Fetch the customer group ids from GET api/rest/customergroups (admin API role only, can be cached, does not change often) All Customer Groups should be assigned to HUB Quote related Shopping Cart Price Rules WARNING: creating an active rule with no conditions or actions and a discount will result in the rule being applied to all ALTA carts for the given websites. The admin UI for Actions says "leave blank for all products" and for Conditions it says "leave blank for all items". WARNING: when creating a product specific rule (by_percent, by_fixed) for a particular HUB Quote, discount_qty should always be specified This prevents abuse where a consumer could change their ALTA cart item quantity before placing their order, getting more total discount than the merchant intended

customer_group_ids: 0=guests/logged out, 1+=logged in. all Customer Groups should generally be assigned to HUB Quote related Shopping Cart Price Rules to offer a discount to logged in Customers only, omit 0. description: an internal textarea for whatever discount_hidden present this product-level rule's Discount Amount as an Item Price reduction, rather than as part of the Discount subtotal can only be used with by_percent and by_fixed product-level simple_actions is_active: 0=Disabled, 1=Enabled (API DELETE is not allowed, instead set this to 0) name: used internally in the Magento admin panel, globally scoped. use a naming convention. does not have to be unique. simple_action by_fixed per item fixed amount off discounts by_percent per item percentage off discounts considers previously applied discounts applying before or after a by_fixed rule for the same product will change the total discount amount two 10% discounts is not the same as a single 20% discount as discounts are applied sequentially cart_fixed: per cart fixed discounts cart_by_percent: per cart percentage discounts considers previously applied discounts of other types does not consider previously applied cart_by_percent discounts (two 10% cart_by_percent rules is 20% off) always applied last sort_order only impacts other cart_by_percent rules item discounts (by_fixed and by_percent) must always specify particular product matching conditions with actions_deserialized, or the rule will affect all cart products! these rule types do not consider previously applied discounts, so sort_order does not matter sort_order an unsigned int which controls the order in which salesrules are applied default value is 1000 HUB Quote price-matching salesrules are added with sort_order 5 (so never add anything with a sort_order of 5 or less!) sort_order should always be above 5 so that HUB Quotes price matching salesrules can be dynamically added as needed changing the order of salesrules application can change your final discount amount and grand total! e.g. you can take 20% off of a product and then $20 off of the product, or vice versa, depending on sort_order cart_by_percent rules are applied after all other rules, so sort_order only impacts the order of cart_by_percent rules application store_labels store scoped, non-unique, and publicly visible for coupon code rules if specified, rule labels will show for Specific Coupon rules, in the subtotals section of the ALTA checkout and cart pages and in order confirmation emails HUB Quotes Conditioned specific coupon rules can just set the store_id 0 store label, since hubquote_id locks the rule to the HUB Quote's particular (website and) store anyway. The rule will only be applied on a particular store_id. stop_rules_processing: if this rule applies, do not attempt to apply any other rules, the discounting is complete website_ids: cannot contain 0, "All Websites" rules do not exist
actions_deserialized: the actions to take when the rule applies
conditions_deserialized: the conditions under which the rule applies
coupon_code: must be unique globally! Consider appending the HUB QUOTE ID and/or the AVB ID/store code.
coupon_type: 1=No Coupon (default), 2=Specific Coupon, 3=Use Auto Generation
